# LEADERS company / report / leader-profile 审计与实施计划

审计日期：2026-09-25。范围：`assets/data/leaders-*`、`assets/js/leaders-*`、Darwin benchmark、`docs/_pages/leaders-scorecard.html`、相关 Sass、校验脚本与研究底稿。本文先记录改动前状态，再记录实施与验收；不把模型分数当成投资、雇佣或准入建议。

## 改动前审计结果

| 优先级 | 发现与证据 | 影响 |
|---|---|---|
| P0 | `findCompany` 以单一模糊匹配阈值直接返回首名；数据库中 `HBM`、`Comirnaty`、`Dupixent`、`mRNA` 分别被两家企业共用。 | 同一查询可能被错误归属，比较输入也可能静默选错公司。 |
| P0 | `leaders-scoring.mjs` 对缺失或无效分数返回 0，证据系数对未知等级回落到 C；数据校验接受可转数字的字符串。 | 错误数据可能被显示成正式低分，而不是拒绝评分。 |
| P1 | 站内文章企业的结果页不渲染 `renderReferences`，且 `reference_summary` 全库为空；`sources` 缺失 17 家。 | 读者难以沿页面追溯评分资料，站内评论容易被误认为原始证据。 |
| P1 | 271 家中 240 家的 `last_reviewed` 为 2026-05-02、13 家为 2026-04-30、18 家未标注。页面只在总表/对比显示日期，查询结果没有复核时效。 | 2026-09-25 查看时，读者可能误以为评分均已近期复核。 |
| P1 | Darwin benchmark 在独立脚本中另写均分与偏差计算；主评分页面用证据调整分比较 Darwin，审计脚本用 LEADERS 简单均分比较。 | 同一“偏差”在不同入口口径不一，解释与人工复核清单可能冲突。 |
| P1 | 页面把企业管理评分称为“Leader Profile”，但 271 条记录没有结构化的具体领导人履历、任期、个人证据链；实际是 company-level management assessment。 | 容易把企业层面的推断误读为对具体个人的档案/判断。 |
| P2 | “报告”只有动态结果与复制查询链接，没有带版本、复核日期、来源和使用边界的打印/导出视图。 | 团队分享与复核困难；打印页面会混入导航、表格、对比等非报告内容。 |
| P2 | 搜索权重切换会在未命中时回退显示第一家企业；总表公司名对外部来源直接跳转。 | 操作反馈不准确，进入正确企业报告的路径不够清楚。 |
| P2 | 数据校验未系统检查 rubric 权重、评分维度、日期、URL 协议与别名冲突；测试只有少数算术断言。 | 结构错误可能到浏览器才显现，难以防止回归。 |

边界：本次不凭现有代码推断 271 家企业的新事实、不批量修改任何企业分数或将缺失日期补成“已复核”。外部资料真实性、证据等级 A/B/C 与收费专业报告承诺需要独立人工核验；本轮提供可见标识与复核清单，不伪造结论。

## 实施计划（按依赖顺序）

1. 抽出共用的评分与企业解析逻辑：严格拒绝无效分数/模型，唯一精确别名优先，歧义别名只显示候选，不自动生成企业结果；建立测试覆盖。
2. 统一查询、比较、总表和 Darwin benchmark 的分数/偏差口径与展示精度；清楚区分原始七项均分、阶段加权分和证据调整分。
3. 增强数据与模型校验：检查评分数字、权重、等级、日期、URL；输出非阻断的资料缺失、复核超期和歧义别名清单，保留现有分数。
4. 完善 company-level 管理画像：显示模型版本、复核日期与时效、可追溯资料、站内文章与外部资料的区别；对缺失项给出明确状态，不把公司评分冒充个人档案。
5. 增加可打印的当前企业简报：打印仅保留当前公司、分数拆解、风险、跟踪点、来源、生成日期和使用边界；浏览器“打印/另存为 PDF”不引入服务端或第三方库。
6. 优化 UI/UX：未知查询与权重切换保持原状态；总表企业名进入站内查询报告；歧义候选可选；移动端和打印版避免横向溢出；中英固定文案完整。
7. 验证：评分与匹配单元测试、数据/模型校验、Jekyll build、完整 `site:check`、生成 HTML 检查，能运行时补桌面/移动截图。

## 验收标准

- 歧义别名不会静默归属；精确公司名称/唯一别名、合法近似查询仍可用。
- 无效模型/分数在测试或构建中显式失败，不显示看似真实的 0 分。
- 查询与 benchmark 对相同企业使用同一偏差定义，并显示其计算口径。
- 查询结果有来源、复核日期/缺失状态、模型版本与非个人档案说明。
- 打印只输出当前企业简报；无当前企业时不能误导为已有正式报告。
- 原站点 URL、文章和现有评分数据不被批量改写，旧查询链接继续有效。

## 实施记录

已执行：

1. `leaders-scoring.mjs` 对缺失、字符串、越界评分和无效证据系数显式报错；评级与页面显示的 1 位小数一致。新增共用的 Darwin−LEADERS 简单均分差值函数，并供主页面、benchmark 与审计脚本使用。
2. `leaders-search.mjs` 将精确企业名称、唯一别名与模糊候选分开处理；共享别名不再直接归属首名。主查询和对比输入对歧义给出反馈，对比下拉不推荐共享别名。切换阶段权重时保留未命中的原查询；总表企业名链接改为站内结果。
3. 查询结果始终显示资料区，同时明确“资料链接不代表逐项独立验证”；补充模型版本、最后复核日期/缺失及半年超期提示，区分企业管理画像和个人档案。增加当前企业简报的打印/浏览器另存 PDF 视图，包含七项分数、Darwin 均分与差值、风险、跟踪点、来源和日期。
4. benchmark 表头和方法文案说明差值只对比两个模型的简单均分；接近的分数不再宣称互相验证。数据校验现在检查 rubric、严格数字、日期、URL，并输出不阻断发布的人工复核队列。

验证：`npm run leaders:test`、`npm run leaders:validate`、`npm run leaders:audit`、`npm run site:build`、完整 `npm run site:check` 均通过；站点检查覆盖 251 个生成 HTML、内部链接、Sass 和 CSS 预算。尚未做浏览器截图或真实打印机/PDF 的人工视觉验收。

人工复核队列：18 家缺复核日期、17 家缺单独的公开资料 URL、4 个跨企业共享别名；另有 rubric 审计的 25 条模型偏差/平分警告。旧分数、证据等级和历史资料未被擅自改写。**这些是资料治理任务，不是可由代码安全自动填充的缺陷。**

下一轮需要经编辑核实再做的能力：逐维度来源与证据时间戳、评分变更历史/快照、具有可核验履历的个人 Leader Profile、专业报告的交付规范与权限。没有对应事实、授权或底稿前，不将这些页面伪装成已完成的个人档案或已核证报告。
