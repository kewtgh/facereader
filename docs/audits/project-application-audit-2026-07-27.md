## 3. 审计限制

本地静态站已成功启动，但当前会话没有可用的内置浏览器实例，无法完成真实浏览器截图和点击回归。因此本轮 UI 审计使用：

- 构建产物、链接、可访问名称和脚本语法检查

最终验收仍应在可用浏览器或 CI 浏览器环境补一次多视口视觉回归。本限制不影响下列已经由代码和数据直接证明的问题。

## 4. 发现与优先级

### P1：必须修复

#### A-01 LEADERS“证据调整分”公式失效

`evidenceAdjustedScore()` 同时在分子和分母乘入同一个证据系数，系数会完全约掉，导致 A、B、C 证据等级的“证据调整分”与阶段加权分始终相同。

影响：

- 业务页面声称存在证据折扣，但实际没有执行。
- B/C 级数据被展示成与 A 级相同置信度。
- Darwin 偏差、评级档位和企业对比都使用了错误结果。

修复方向：阶段加权分乘证据系数，并增加可执行回归测试，防止公式再次失效。

#### A-02 每页重复内联大型 i18n 数据和逻辑

`_includes/footer/custom.html` 将中英文 UI 字典及三段业务脚本内联到每个页面。

量化结果：

- 243 个 HTML 页面内联脚本合计约 6,164,198 字节。
- 平均每页约 25,367 字节，不可跨页面缓存。
- UI 语言、返回评级页和评分表增强逻辑耦合在 footer 模板中。

影响：HTML 体积、缓存命中、维护成本和 CSP 兼容性均较差。

修复方向：生成可缓存的 UI 字典脚本，并把通用逻辑拆为外部脚本；footer 仅负责按顺序引用。

#### A-03 图片尺寸与加载策略不完整

生成页面共有 935 个图片实例：

- 922 个缺少 `width` 或 `height`。
- 508 个缺少 `loading`。
- 506 个左右缺少异步解码提示。

影响：浏览器无法在图片下载前稳定预留空间，容易产生 CLS；文章中的远端图片还会过早参与加载。

修复方向：构建时为本地 PNG/JPEG/GIF/WebP 自动补尺寸；为非首屏、非站点 Logo/作者头像/页面 Hero 图片补 `loading="lazy"` 与 `decoding="async"`。

#### A-04 构建工具和 Source Map 被发布

`assets/scripts` 下的校验、Algolia 管理和生成脚本被原样复制到 `_site`；`main.min.js.map` 也进入生产产物。

影响：

- 发布了用户不需要的内部工具和规则文件。
- 扩大生产产物与实现细节暴露面。
- 增加部署体积。

修复方向：从 Jekyll 输出中排除 `assets/scripts` 和生产 Source Map，保留仓库内开发能力。

### P2：应在本轮完成

#### A-05 LEADERS 查询状态不可分享

企业查询和权重口径只存在于内存；刷新、复制 URL 或浏览器前进/后退不能恢复结果。

改进：引入 `company`、`stage` 查询参数，增加“复制查询链接”动作和可访问状态提示。

#### A-06 企业总表只能按行业和地区筛选

271 家企业的总表不能按企业名称、股票代码或别名直接过滤，用户需要水平滚动和分页查找。

改进：增加名称/别名即时过滤，与行业、地区过滤组合工作。

#### A-07 标签页缺少标签搜索和完整空状态

标签较多，但只能逐组浏览；无效 `?tag=` 会隐藏全部文章，却没有清晰的无结果提示。平滑滚动也未遵循 `prefers-reduced-motion`。

改进：增加标签名称/说明搜索、结果计数和 live status；补无结果状态；尊重减少动态效果偏好。

#### A-08 Algolia 依赖在用户打开搜索前加载

每个启用全站搜索的页面都会在 DOM 就绪后加载 InstantSearch CSS、Algolia 客户端和 InstantSearch JS，即使用户从不打开搜索。

改进：搜索面板首次打开时才加载远端依赖；重复打开只复用已经初始化的实例。

#### A-09 Darwin 基准逻辑内联在内容文件中

数据请求、计算和表格渲染直接写在 `darwin-leaders-benchmark.html` 内，难以缓存和复用，也未显式检查 HTTP 状态；数据表缺少 caption。

改进：抽取为外部脚本，补响应状态检查、空数据保护、可访问 caption 和加载状态。

#### A-10 缺少生成 HTML 与评分公式的防回归测试

当前检查可以发现数据结构和链接错误，但不能发现：

- 证据系数被抵消；
- 生产目录误带构建脚本或 Source Map；
- 本地图片缺尺寸；
- 表单控件失去可访问名称；
- 重复 `id` 或不安全新窗口链接。

改进：新增评分公式单测和生成 HTML 审计，并纳入 `site:check`。

### P3：低风险质量问题

#### A-11 主脚本残留无效 Liquid 占位符和死代码

`assets/js/_main.js` 进入 Uglify 前不会经过 Liquid，标签折叠文案中的 `{{ ... }}` 可能原样进入生产脚本；对应 `toggle-tags` / `tags-wrapper` 元素当前又不存在，属于不可执行死代码。

修复方向：删除死代码；保留实际使用的标签组切换并增强 `aria-hidden`。

#### A-12 footer 社交链接经确认属于匿名占位（保留）

审计最初将 footer 中指向平台首页或暂未启用的链接视为待清理项。用户随后确认，这些作者与页脚标签是出于个人安全和匿名运营而有意保留的占位结构，后续会补充账号。

处理结论：不删除、不改名，也不把匿名期占位视为缺陷。此项从整改范围撤回，并作为后续修改必须保留的用户约束。

#### A-13 robots.txt 重复声明通用 User-agent

两个 `User-agent: *` 组分散维护，虽然主流爬虫通常会合并，但不必要地增加解析差异和维护风险。

修复方向：合并为一个通用组，专用 bot 阻止规则保持独立。

### 二次回查补充

#### A-14 Algolia 初始化器仍会重复内联

首次整改已做到“用户打开搜索后才加载远端依赖”，但二次产物统计发现初始化器本身仍由 include 写入每个页面。它不访问远端时也会重复增加 HTML 和 CSP 负担。

修复：将初始化器改成 Jekyll 生成的 `assets/js/algolia-search.js`，页面只保留带版本号的外部引用；生成 HTML 门禁同时阻止完整 UI 字典或 Algolia 初始化器重新内联。

#### A-15 分享链接依赖内联 onclick

文章分享按钮用四段重复的 `onclick="window.open(...)"` 创建弹窗，增加 CSP 收紧难度；Bluesky 链接还缺少 `aria-label`。

修复：使用标准 `target="_blank"` 与 `rel="noopener"`，删除内联事件，并补齐 Bluesky 可访问名称。作者与 footer 的匿名运营链接未被改变。

## 5. 本轮建议并纳入实施的新功能

本轮只引入与现有产品直接相关、能够完成验证的功能：

1. 可分享、可复制、可由前进/后退恢复的 LEADERS 查询。
2. 企业总表名称/别名即时筛选。
3. 标签名称/说明即时搜索和清晰空状态。
4. 自动图片尺寸与懒加载构建增强。
5. 面向评分公式和生产 HTML 的自动质量门禁。

不在本轮引入账号、支付、后台 CMS 或新的外部服务，避免在没有业务权限、数据模型和运营流程的情况下扩大系统边界。

## 6. 审计结论

项目基础设施整体健康，近期依赖现代化、Sass 迁移、Algolia 保护和数据治理工作质量较高；本次没有发现泄露的密钥、已知 npm 漏洞、断链、重复 ID 或图片替代文本缺失。

当前最重要的问题不是“页面是否能打开”，而是一个会改变评级结果的业务公式缺陷，以及静态站点可缓存资源、图片稳定性和生产输出边界仍不完善。本轮计划将优先修复这些问题，再补齐查询、筛选、无障碍和自动化门禁。
