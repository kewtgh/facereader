# FaceReader 项目与应用审计（2026-10-24）

## 从目标推导要求

FaceReader 是独立双语长文博客，附有 LEADERS 企业评分阅读工具。主站为 `facereader.witbacon.com`，分站 `faceread.witbacon.com` 服务不便访问主站的读者；两站共用内容，主站保持 canonical。读者应当能够找到适合自己语言的文章、理解文章上下文和预计阅读成本、沿系列继续阅读，并在不接受可选第三方服务时完成阅读。作者需要可重复的构建、明确的公开边界以及能阻止真实回归的发布检查。

因此沿用 Jekyll、静态托管、现有 permalink 和评分模型。当前规模不需要数据库、账户体系或付费 AI 服务；增加服务端只会增加运维、隐私和故障面。本次建议的新功能全部纳入配套计划，选择能直接改善发现、阅读和回访的功能。

## 方法与基线

- 检查配置、插件、模板、前端脚本、评分数据校验、发布工作流和实际生成产物。
- 在本地以 production 模式构建，使用无权限占位搜索密钥；浏览器外部请求被阻断，不调用线上搜索、统计、评论或付费服务。
- 原始 `site:check` 通过：255 个 HTML、1366 张图片、无图片尺寸/加载属性错误；CSS 为 205652 bytes raw / 35843 bytes gzip（预算 36864）。
- 原始 `site:browser` 通过：Chromium headless shell 1248，桌面、平板、手机；包含语言、归档分页、系列、公式、注释、评分查询、失败重试等既有路径。
- 上述通过不能证明下列问题不存在。浏览器工具原本没有声明在项目依赖中，CI 也没有执行这套浏览器检查。

## 发现、影响与处理

|编号|优先级|证据与影响|采用的修复或新功能|
|---|---|---|---|
|A01|高|`_site/scripts/` 中实际包含 Ruby 测试、HTML 审计和 Vercel 安装/构建脚本。`banner.js`、`staticman.yml`、`vercel.json` 也被复制到站点。现有产物检查仅覆盖 `assets/scripts` 和 `research`。|排除根目录构建及部署文件，扩充产物边界检查，保持公开内容与工程文件边界。|
|A02|中|可见性和 locale 规则分散于 `language_archives.rb`、`series_index.rb` 和 Liquid 模板，写法有差异；推荐模板扫描所有文章，无语言、hidden 或翻译组过滤。|统一内容策略；在构建期生成文章目录和同语言相关推荐，排除自身、同翻译组及不可见文章。|
|A03|中|`page__meta.html` 对所有语言按字符数除以 450，忽略配置中的阅读速率；英文按字符估算明显偏大。|按中文字符与其他语言单词分别估算，使用配置速率及文章覆盖值，向上取整并至少 1 分钟；集中生成数据。|
|A04|中|当前搜索依赖两个外部 JS 库及 Algolia。依赖失败后只有重试和归档链接，读者无法继续按关键词找文章；查询服务失败也缺少明确恢复入口。|新增 `/search/` 双语本地文章搜索，使用随站发布的精简目录；支持关键词、主题、分享链接、历史状态、加载失败重试、无结果和无 JS 退路。接入搜索面板及 Algolia 错误入口。|
|A05|中|目前没有读者明确保存长文的途径；回访需依赖浏览器书签或再次翻查归档。|新增“稍后阅读”和 `/reading-list/`，只在读者点击时保存文章 URL，限定条数、校验数据，支持移除、跨标签同步及存储不可用提示。|
|A06|中|production 页头自动请求 Google Analytics；评论脚本自动插入 Disqus。两个服务均会在读者未操作时开始请求。|访问统计默认关闭，页脚提供可撤回的明确偏好；尊重浏览器隐私信号。评论按次点击加载，提供失败重试；更新双语隐私说明，准确说明本地存储与第三方请求。|
|A07|中|统一 RSS 混合中英文；英文读者订阅后会收到大量中文条目。|保留 `/feed.xml`，新增中文与英文 Atom feed，并在页面和页脚提供对应入口；使用同一可见文章目录。|
|A08|中|`last_modified_at` 存在 5 处格式错误：`T7:`、`T9:`、`T010:`；现有校验没有拦截。|仅规范这些时间写法，保留原日期、时区和含义；校验所有文章日期元数据，防止再次进入构建。|
|A09|中|`site.xml` 为旧手工 sitemap，日期固定且不会随文章新增而更新。分站域名本身有效，并非错误；需与现有主站 canonical 策略保持同步。|保留旧 URL，将其改成引用 canonical `/sitemap.xml` 的 sitemap index，保留主站与分站部署入口。|
|A10|中|404 页面只有中文道歉文案和无链接的“在本站中查询”，缺少可执行的恢复路径。扩展到 320px 的回归另发现页眉宽度为 351px，菜单溢出屏幕；搜索实际点击区域也偏小。|404 提供双语搜索、归档及首页入口；窄屏保留完整品牌文字并收起重复图标，搜索按钮提供 44px 点击区。用户确认社交平台首页链接是匿名设计，按原样保留，不作为缺陷。|
|A11|中|Playwright 未声明依赖，测试截图路径固定为旧审计日期，GitHub Pages 在上传前只跑静态检查；Vercel 脚本的 Node 24.18.0 与统一版本文件 24.21.0 不一致。|锁定可复现的 Playwright 依赖，支持配置截图目录，上传前执行离线 Chromium 回归并保留失败截图；已有部署脚本读取统一 Node 版本。|
|A12|低|阅读进度条按整个文档高度计算，包含作者、评论、推荐和页脚；正文结束时进度仍未完成。|文章进度以正文范围计算，非文章页面不显示阅读进度，避免误导。|
|A13|中|用户追加要求核实并更新依赖。npm 注册表确认 Algolia 客户端及 InstantSearch JS/CSS 有稳定更新；运行时和 Bundler 也有稳定补丁更新。|核实官方运行时、npm/RubyGems、浏览器库与 Actions；采用最新稳定版及 LTS，更新锁文件、CDN 引用、运行时和部署文档，重新完整验证。|

## 设计判断与内容边界

LEADERS 已具备模型校验、歧义消解、重试、对比上限和计算解释，基线回归通过。现有评分语义复核提示仍属于作者编辑判断，不能以代码测试通过代替事实或评分正确性。本次不改写文章观点、评分结论或历史 URL；只修复可证明的元数据问题。按用户补充，分站只作为背景保留，不做专项改造，不将 `faceread.witbacon.com` 视作错误域名。

本地搜索明确检索标题、摘要、标签和主题，不能宣称全文搜索或离线缓存整站；稍后阅读不保存浏览历史，不提供账户同步或下载。统计关闭和按需评论是产品隐私选择，不构成法律合规认证。未执行真实第三方评论登录、线上统计、远端 CI 或生产部署。
